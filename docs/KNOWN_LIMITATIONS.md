# 已知限制与安全注意事项

Better Canvas 仍在持续整合和验证中。功能代码存在不代表它已在所有 Obsidian 版本、主题、桌面端和移动端验证。逐项实现情况及与上游项目的差异请见[功能整合矩阵](INTEGRATION_MATRIX.md)。

## 兼容性

- **内部 API 与 DOM：** Portal 文件同步、元数据缓存、内置 Backlinks 侧栏桥接、PDF 单页渲染、特定连线路由、节点样式和键盘快捷键部分依赖 Obsidian 内部接口或 DOM 行为。插件附带的链接浏览器会扫描 Markdown 元数据和其他 Canvas JSON；它不代表已完全接入 Obsidian 全局搜索、关系图和所有元数据缓存行为。Obsidian 更新可能改变这些行为。
- **复杂 Canvas：** 多父节点、循环关系、嵌套分组以及复杂跨分组/跨 Portal 连线可能无法获得理想布局或路由；建议先在测试 Vault 验证重要工作流。
- **静态导出：** PNG/SVG 导出会把内容绘制成静态图像，不会执行交互 HTML。嵌入图片和 PDF 页面预览受到资源体积预算限制；复杂 Markdown 和 Obsidian 原生 DOM 并不能保证像素级一致。
- **移动端及主题：** CI 不会启动 Obsidian 图形界面。触控、缩放、选区、菜单、主题 CSS 和特定 DOM 行为需在目标版本实测。

## 节点形状与边框

非矩形形状（Diamond、Hexagon、Document、Pentagon 等）的轮廓由 `.canvas-node-container` 上的 CSS `clip-path` 决定，边框改用沿轮廓的 SVG `mask-image` 描边环绘制（`styles.css` 的 `--bc-shape-outline` / `--bc-ring-*`）。因此：

- 形状节点的卡片投影不显示：原生 `box-shadow` 会被 `clip-path` 裁掉，选中态用描边环颜色（`--color-accent`）表达。
- 虚线、点线在多边形长边与短边上的段长不完全一致，因为描边掩膜按节点框等比缩放。
- 形状只影响外观：连线端点、框选、缩放手柄、编组边界仍按矩形计算；导出 PNG/SVG 由导出渲染器单独绘制这些形状。
- 极端尺寸（极窄或极扁）的节点上，描边环与轮廓的重合度会下降。

## Canvas Portal

Portal 以单层镜像为主：引用的 `.canvas` 中的节点和连线会映射到 Portal 内，节点编辑与删除会同步回源文件，跨 Portal 的连线会映射到 Portal 框。Portal 内创建的普通节点及同 Portal 内的连线会尝试写回源画布；也保留了显式命令“在选中 Canvas Portal 中创建文本节点”。新建分组框只有在整个矩形都处于 Portal 内容范围内时才会自动归属。

嵌套 Portal、复杂跨 Portal 连线和并发源文件修改仍需完善。由于 Portal 会修改源 Canvas 文件，使用重要数据前请先备份，并在测试 Vault 验证。

## PDF

固定分页支持文本提取与选择、从选中文本创建关联摘录节点、页面图像上下文，以及随 `.canvas` 保存的手绘和文字批注。页面工具栏包括红/蓝笔、荧光笔、橡皮擦、撤销和清空；批注可以导出为包含高亮和手绘笔迹归一化坐标的 Markdown 汇总。

当前仍不是完整 PDF 编辑器：不会修改 PDF 原文件中的原生文字高亮对象；不支持整份文档一键自动 OCR，也没有高级多页批注管理。AI OCR 按页码或范围处理，每批最多 20 页。触控、页面缩放、旋转页面和选择坐标仍需在目标环境验证。

## AI 服务

- 不同 provider、模型、网关和账号权限支持的功能不同。模型列表发现失败时可手动输入模型名；图片生成、图片输入、PDF、YouTube 视频、URL context 和 grounding 能力应分别确认，不能根据一次普通文本请求成功就推断全部可用。
- 网页导入采用尽力而为的正文提取；JavaScript 动态页面、登录墙和反爬页面可能无法读取。YouTube 字幕导入已移除；Gemini 直接分析公开视频依赖对应模型能力和账号权限。
- Codex CLI 和 OpenCode ACP 均使用各自配置的模型服务，不保证离线处理。OpenCode ACP 当前是文本后端，不接收图片或文件上下文。
- 批量 Prompt 每次最多处理 20 篇 Markdown。发送正文前需要用户选择文件夹并确认；仍应避免向不可信服务发送隐私内容。
- HTML 预览使用 sandbox iframe，不授予同源权限、表单、弹窗或顶层导航权限；预览代码仍应先检查其内容和外部资源行为。

## MCP 与本地进程

远程 MCP 支持 Streamable HTTP 和旧式 SSE，本地 stdio 通过配置的可执行文件、参数、环境变量及工作目录启动服务。工具执行前会展示工具名称和参数供检查；AI 提议的调用也必须先确认。

本地 stdio 服务在当前用户权限下运行，可能访问该用户可访问的本地文件与网络。只配置可信服务，不要将 token 放入仓库、Issue 或截图。MCP 文本结果会创建关联节点，支持的 PNG/JPEG/WebP/GIF 图片结果会写入 Vault 附件。插件对本地会话进行有界复用（最多 4 个），空闲 5 分钟后关闭，并在插件卸载时清理子进程；进程和协议异常会导致会话被丢弃。

## 数据与隐私

- API Key 存储在本地 Obsidian 插件设置中；使用 AI 时，提示词、选中节点内容和所需上下文会发送给配置的服务。
- 本地 CLI 也可能把上下文发送到其登录配置的模型供应商。使用本地命令不代表离线处理或对其他本地文件的绝对隔离。
- 在将私人笔记、PDF 内容或文件正文交给外部服务之前，请检查服务商的数据处理政策，并仅发送完成任务所需的内容。
- 对可能修改源 Canvas、Vault 文件或外部系统的工作流，建议先备份，并在执行工具或导出之前核对内容与参数。

功能实现状态、验证覆盖与上游功能差异详见 [功能整合矩阵](INTEGRATION_MATRIX.md)。
